# Sprint_10_2

Итоговый проект курса «Инженер по тестированию» (Яндекс Практикум): API-автотесты для учебного сервиса [«Доска объявлений»](https://qa-desk.education-services.ru/) на `requests` и pytest. Документации по API нет, поэтому эндпоинты, тела запросов и ответы сервера получены исследованием трафика фронтенда в Chrome DevTools и Postman.

## Стек

- Python 3
- pytest
- requests
- Faker — генерация тестовых данных

## Структура проекта

```
Sprint_10_2/
├── conftest.py        # фикстуры: пользователь, регистрация, авторизация, второй пользователь, объявление
├── urls.py            # базовый URL и эндпоинты API
├── data.py            # тестовые данные: категории, города, состояния товара
├── helpers.py         # генерация email, пароля, имени, текста и цены
└── tests/
    ├── test_register.py     # TestRegister — регистрация пользователя
    ├── test_login.py        # TestLogin — авторизация пользователя
    ├── test_create_add.py   # TestCreateAdd — создание объявления
    ├── test_edit_add.py     # TestEditAdd — редактирование объявления
    └── test_delete_add.py   # TestDeleteAdd — удаление объявления
```

## Покрытые ручки

| Ручка | Метод | Тесты |
|-------|-------|-------|
| `/api/signup` | `POST` | Регистрация с уникальным email — 201; повторная регистрация с существующим email — 400 |
| `/api/signin` | `POST` | Авторизация зарегистрированного пользователя — 201 |
| `/api/create-listing` | `POST` | Создание объявления в случайной категории — 201 |
| `/api/update-offer/:id` | `PATCH` | Изменение `name` / `description` / `price` и `category` / `condition` / `city` (параметризация) — 200; редактирование чужого объявления — 401 |
| `/api/listings/:id` | `DELETE` | Удаление своего объявления — 200 |

Запросы на создание и редактирование объявления отправляются как `multipart/form-data`, авторизация передаётся заголовком `Authorization: Bearer <token>`.

## Запуск

1. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install pytest requests faker
   ```

2. Запустите тесты:

   ```bash
   pytest tests -v
   ```

## Задание

Напиши API-автотесты для учебного сервиса «Доска». Документации по API ещё нет, а ручной тестировщик уже передал сценарии — их нужно покрыть автотестами.

### Подготовь проект

- Установи браузер Chrome.
- Создай в IDE новый проект `Sprint_n`.
- Из библиотек понадобится `requests`.
- Изучи исследование трафика в DevTools и работу с API-клиентом для отладки и отправки HTTP-запросов (например, Postman).

### Тестовые сценарии

#### 1. Регистрация пользователя

- Успешная регистрация нового пользователя с уникальным email. Для каждого теста регистрации обязательно генерировать новый email.
- Повторная регистрация пользователя с email, который уже есть в БД.

#### 2. Авторизация пользователя

- Успешная авторизация ранее зарегистрированного пользователя.

#### 3. Создание объявления

- Успешное создание объявления в любой категории.

#### 4. Редактирование объявления

- Успешное редактирование любого поля объявления.
- Редактирование объявления, созданного не тем пользователем, под токеном которого производится редактирование.

#### 5. Удаление объявления

- Успешное удаление объявления.

### Напиши тесты

> **Важно!** Все ответы сервера, тела запросов и т. д. нужно получить самостоятельно, исследуя запросы с фронта на сервер.

- Раздели тесты по тематике или функциональности.
- Логические методы вынеси в отдельные модули.
- Не нужно создавать отдельный класс для каждого теста — тесты на одну функциональность объединяй в один класс.
- Все тесты должны лежать в директории `tests`.
- Проверь, что тесты запускаются.

## Критерии оценки

- Нейминг методов корректный.
- Для каждого блока проверок тесты лежат в отдельном классе и отдельном тестовом модуле.
- Написаны тесты на функциональность «Регистрация пользователя».
- Написаны тесты на функциональность «Авторизация пользователя».
- Написаны тесты на функциональность «Создание объявления».
- Написаны тесты на функциональность «Редактирование объявления».
- Написаны тесты на функциональность «Удаление объявления».
- Для предусловий используются фикстуры.
- Все тесты независимы.
- Тестовые данные хранятся в отдельном модуле.
- Метод генерации email хранится в отдельном модуле.
- В тестах отсутствуют условия — тест всегда однозначен.
- В коде отсутствуют принты и закомментированный код.
